# Mermaid Architecture Diagrams

Create structured, high-contrast, production-ready Mermaid architecture diagrams, workflows, and system design documentation stored directly in `docs/architecture/`.

## 🎯 Purpose

Deliver diagrams-as-code that render natively in GitHub, GitLab, Obsidian, wikis, and documentation pages without external tooling dependencies, while supporting optional PNG/SVG exports via Mermaid CLI (`mmdc` or `npx @mermaid-js/mermaid-cli`).

## 📁 Storage Location (`docs/architecture/`)

All diagram artifacts and architecture documentation generated by this skill are saved in `docs/architecture/`, consistent with `drawio-architecture`:

```text
docs/architecture/
├── system-architecture.md             # Architecture docs with embedded Mermaid blocks
├── <diagram>_<type>_<title>.mmd       # Raw Mermaid source file
├── <diagram>_<type>_<title>.png       # Optional raster export
└── <diagram>_<type>_<title>.svg       # Optional vector export
```

## 🛠️ How it Works

1. **View Selection** — Selects the appropriate diagram type: C4 / Architecture (component boundaries), Sequence (API/auth flows), Activity (business logic/ETL), Deployment (cloud/K8s), or ER/Class.
2. **Code-to-Diagram Extraction** — Reverse engineers architecture and interactions from code (controllers, services, entities, Docker Compose, Helm, Terraform).
3. **Resilient Validation** — Validates syntax before embedding with `scripts/resilient_diagram.py`. When errors occur, applies known fixes from `troubleshooting.md`.
4. **High-Contrast & Unicode Styling** — Always applies `color:` inside `classDef` for readability across dark and light themes, enhanced with semantic Unicode icons.
5. **Orchestrator Coordination** — In Phase 5 (Verification & QA), runs immediately after `/drawio-architecture` so both editable `.drawio` files and native Markdown diagrams stay synchronized.

## 🚀 Usage

Use this skill when:
- Designing or documenting system architecture, microservices, or cloud deployments.
- Visualizing API interactions, authentication flows, or data pipelines.
- Updating documentation in `docs/architecture/` during Orchestrator Phase 5.
- Invoked explicitly: `/mermaid-architecture` (or "generate mermaid diagram", "diagrama mermaid").

## 🔗 Correlation

- **Companion**: `drawio-architecture` creates editable `.drawio` XML files; `mermaid-architecture` creates native Markdown Mermaid diagrams in `docs/architecture/`.
- **Upstream in Phase 5**: `drawio-architecture` runs first; `mermaid-architecture` runs immediately after.
- **Downstream**: `create-readme` references the architecture diagrams in `README.md`.
- **Orchestration**: `orchestrator` coordinates both diagram skills during the final release gate.
